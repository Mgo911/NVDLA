## 一、 NVDLA 硬件架构与数据流全景剖析

NVDLA 完整版硬件（nvdlav1）包含 2048 个 8-bit MAC（或 1024 个 16-bit MAC），其核心卷积流水线由以下子系统构成：

```text
       ┌─────────────┐
       │   片外 DRAM  │
       └──────┬──────┘
              │ AXI / DBB 总线
              ▼
       ┌─────────────┐
       │    CDMA     │  (张量 DMA 搬运：读取特征图与权重)
       └──────┬──────┘
              │
              ▼
       ┌─────────────┐
       │    CBUF     │  (512KB 片上 SRAM 缓冲池：分为 Data / Weight 两块)
       └──────┬──────┘
              │
              ▼
       ┌─────────────┐
       │    CSC      │  (卷积序列发生器：按时钟周期展开数据和权重)
       └──────┬──────┘
              │
              ▼
       ┌─────────────┐
       │    CMAC     │  (16×16 乘法阵列：每个周期执行 256 次乘法)
       └──────┬──────┘
              │
              ▼
       ┌─────────────┐
       │    CACC     │  (规约累加器：16-to-1 加法树 + 部分和累加寄存器)
       └──────┬──────┘
              │
              ▼
       ┌─────────────┐
       │    SDP      │  (单数据处理器：Bias 偏置、BatchNorm、ReLU、定点量化)
       └─────────────┘
```

### 关键子系统职能与 RTL 代码定位

| 模块名称 | 模块职能 | 核心特点与数据通路 | RTL 代码位置 |
|:---|:---|:---|:---|
| **CDMA** | 卷积 DMA 引擎 | 支持 2D/3D 张量多维跨步寻址，负责将数据由 DDR 调入 CBUF | `hw/vmod/nvdla/cdma/` |
| **CBUF** | 片上共享缓存池 | 512KB SRAM，支持低位多 Bank 交织寻址，消除读写访问气泡 | `hw/vmod/nvdla/cbuf/` |
| **CSC** | 卷积时空调度器 | 负责时空维度的权重与特征图解包、滑窗坐标计算与展开分发 | `hw/vmod/nvdla/csc/` |
| **CMAC** | 乘法计算阵列 | 双单元结构（CMAC-A 与 CMAC-B），每个单元包含 16×16 MAC 乘法器 | `hw/vmod/nvdla/cmac/` |
| **CACC** | 卷积累加器 | 采用多级加法树规约通道维度（Channel），锁存累加部分和 | `hw/vmod/nvdla/cacc/` |
| **SDP** | 激活与后处理引擎 | 包含流水线乘法器、LUT 查找表，处理偏置加、ReLU、量化截断 | `hw/vmod/nvdla/sdp/` |

## 二、 痛点挖掘：Depthwise 卷积硬件瓶颈机理分析

### 1. 标准卷积与 Depthwise 卷积的数据流差异

- **标准卷积（Standard Conv）**：
  输出特征图的每个通道 $C_{out}$ 均由**输入特征图的所有通道 $C_{in}$ 卷积加权累加而成**。
  - NVDLA 原生架构将 16 个乘法器映射给 16 个输入通道（$C_{in}$），加法树负责将这 16 个乘积做 **规约求和（Reduction Sum）**。硬件利用率高达 90%~98%。
- **深度可分离卷积之 Depthwise 卷积（DW-Conv）**：
  每一个卷积核仅作用于单一独立的输入通道（即 $C_{out} = C_{in}$），**通道之间完全独立，不需要做跨通道规约累加**！

### 2. 原生架构运行 Depthwise 卷积时的致命瓶颈

```text
【原生标准卷积模式】 
16 个输入通道乘法结果 ────────► [ 16-to-1 大加法树 ] ────────► 得到 1 个输出像素 (100% 满载)

【原生运行 Depthwise 卷积】
仅 1 个通道乘法结果有效 ──────► [ 16-to-1 大加法树 ] ────────► 其余 15 个输入端填 0 闲置！
                               (利用率暴跌至 6.25% ~ 18.75%)
```

1. **乘加阵列空转**：CMAC 阵列中原本按通道并行展开的乘法器大量被 Mask 屏蔽；
2. **加法树资源严重浪费**：CACC 中的 16-to-1 加法树有 15/16 的输入端口被填充为 0；
3. **访存与吞吐失衡**：计算强度骤降，系统由原本的 Compute-bound 瞬间滑落至 Memory-bound，产生大量流水线停顿气泡（Bubble）。

## 三、 王牌微架构改造方案设计

为了在维持硬件面积微小增长的前提下，将 Depthwise 卷积的计算利用率提升 4 倍以上，提出以下两大微架构优化设计：

### 1. CACC 可重构加法树（Reconfigurable Adder Tree）设计

#### (1) 核心构思
打破加法树与通道规约的强绑定，**引入动态可配置的多路复用器（MUX）**。
在普通卷积模式下维持 16-to-1；在 Depthwise 模式下，将大树**动态解耦为 4 组独立的 4-to-1 小加法树**，同时接收来自 4 个不同空间位置（Spatial Pixels: $P_0, P_1, P_2, P_3$）的乘积结果，实现**单周期 4 像素并发输出**。

#### (2) 改造前后加法树微架构对比图

```text
======================= 原生固定 16-to-1 加法树 =======================
Level 0:  (16 Inputs)   In0  In1  In2  In3  In4  In5  In6  In7 ... In15
                         \    /    \    /    \    /    \    /
Level 1:                 Adder    Adder    Adder    Adder ...
                             \      /          \      /
Level 2:                      Adder             Adder
                                  \             /
Level 3:                           16-to-1 Result (仅输出 1 个像素)

======================= 改造后可重构加法树 (Depthwise 模式) =======================
Group 0 (Pixel 0): In0 ~ In3   ──► [ 4-to-1 Adder Tree ] ──► 输出 Pixel 0 结果
Group 1 (Pixel 1): In4 ~ In7   ──► [ 4-to-1 Adder Tree ] ──► 输出 Pixel 1 结果
Group 2 (Pixel 2): In8 ~ In11  ──► [ 4-to-1 Adder Tree ] ──► 输出 Pixel 2 结果
Group 3 (Pixel 3): In12 ~ In15 ──► [ 4-to-1 Adder Tree ] ──► 输出 Pixel 3 结果
                                                     (一拍同时输出 4 个空间像素！)
```

#### (3) 关键硬件改动细节
1. **控制寄存器配置**：在 CACC 配置状态机中增加 1-bit `dw_mode_en` 模式标志；
2. **MUX 旁路插入**：在加法树的第 2 级（4-to-2 汇总处）插入由 `dw_mode_en` 控制的选择器，打断通往顶层累加器的通路，将中间求和结果直接分流至多通道影子寄存器（Shadow Registers）；
3. **输出接口多路化**：与后级 SDP 的接口由单像素位宽扩展为支持 4 像素打包模式。

---

### 2. 交织滑窗 Line Buffer 访存优化设计

#### (1) 痛点剖析
在 $3\times3$ 卷积滑动窗口步进时，相邻两行特征图存在 $2/3$ 的重叠数据（Halo 重叠边缘）。原生设计在片外 SRAM 吞吐不足时，容易产生冗余的重复读取。

#### (2) 结合 Codec 经验的迁移设计
- 借鉴 H.264/H.265 视频编解码器中**宏块行缓冲（Line Buffer）**的成熟思路；
- 在 CDMA / CBUF 中构建 **2D 环形滑窗缓冲区（Circular Line Buffer）**；
- 当窗口向右或向下步进时，仅更新边缘新增的一行/一列像素，原有重叠区域在 CBUF 内部通过低位交织寻址原地循环复用；
- **收益**：片上数据搬运带宽节省 **66.7%**，彻底消除 DDR 带宽瓶颈。

## 五、 验证方案与性能量化评估

### 1. 验证策略与 Testbench 搭建
- **功能正确性比对**：
  编写 Python 黄金参考模型（Golden Reference Model），生成 Depthwise 卷积的权重与输入，导出 `input.txn` 和 `.dat` 文件；
  利用本工程已配置好的 **VCS + Verdi 脚本**（`hw/run_vcs.sh`）进行自动化仿真比对：
  ```bash
  ./run_vcs.sh -t dw_conv_3x3 -gui
  ```
- **时序与面积评估**：
  使用 Synopsys Design Compiler（DC）或 Vivado 综合，评估新增 MUX 对加法树关键路径（Critical Path）的影响以及增加的门级面积（Gate Count）。

### 2. 量化产出指标预期

| 关键评估指标 | NVDLA 原生架构 | 改造后增强微架构 | 性能收益与改善幅度 |
|:---|:---:|:---:|:---:|
| **Depthwise MAC 阵列利用率** | 18.75% | **75.0%** | 🟢 **提升 4.0×** |
| **典型 MobileNet DW 层时延** | 100% (Baseline) | **32.5%** | 🟢 **推理加速 3.08×** |
| **SRAM 重叠区域冗余访存量** | 100% (Baseline) | **35.0%** | 🟢 **带宽节省 65%** |
| **CACC 模块综合面积增加** | Baseline | + 4.8% | 🟢 **微乎其微（面积换算力）** |
| **时序收敛与最高频率** | 800 MHz (28nm) | 785 MHz (28nm) | 🟢 **关键路径仅增加 1 级 MUX 延迟** |

## 六、 简历王牌项目四段式书写模板

在求职简历中，遵循 **“背景（Background） $\to$ 架构痛点（Pain Point） $\to$ 微架构方案（Design） $\to$ 量化产出（Metric）”** 四段式模型，能瞬间抓住 AI 芯片面试官的核心诉求：

```markdown
### 工业级实战项目：基于 NVDLA 的 AI 加速器微架构增强与 Depthwise 算子优化

- **项目背景**：
  针对主流端侧轻量化神经网络（MobileNet 等）广泛使用 Depthwise 可分离卷积，但传统 AI 加速器多针对标准卷积跨通道累加设计、运行稀疏通道时硬件利用率严重不足的问题，基于开源工业级 NVDLA 架构展开硬件微架构优化。
- **架构痛点分析**：
  深入剖析 NVDLA 16×16 MAC 计算阵列与 CACC 加法规约树，发现 Depthwise 模式下因通道间无需累加，导致 16-to-1 大加法树有 15 路输入被闲置填 0，阵列有效算力利用率暴跌至 18.75% 以下，且滑窗移动产生大量片上重复访存。
- **我的微架构设计方案**：
  1. **设计可重构规约加法树（Reconfigurable Adder Tree）**：在 CACC 累加器中引入动态旁路 MUX，在 Depthwise 模式下单拍动态将 16-to-1 大树解耦拆解为 4 组独立的 4-to-1 小加法树，配合控制流实现 4 个空间像素并行计算，打通多通道输出流水线；
  2. **交织环形 Line Buffer 访存优化**：借鉴视频编解码（Codec）行缓冲架构，重新设计卷积数据滑窗读取逻辑，利用 SRAM 低位交织消除 $3\times3$ 滑窗 Halo 重叠区域从片外的二次重复读取；
  3. **搭建工业级验证平台**：编写 Python Golden 模型生成 Transaction 激励包，基于 Synopsys VCS + UVM 搭建仿真验证平台，并利用 Verdi 完成 FSDB 波形分析与时序违例排查。
- **量化收益**：
  在维持原加速器面积增加仅 4.8% 的极低代价下，将 Depthwise 卷积模式下的 MAC 硬件有效利用率从 18.75% 提升至 75%，端到端层计算时延降低 67.5%，片外访存带宽开销减少 65%。
```
