## 一、 优势底气：Codec 与 AI 加速器的技术映射

在芯片设计中，**视频编解码器（Video Codec）与深度学习加速器（NPU）的底层硬件 DNA 重合度高达 70%**。你过去的经验绝非沉没成本，而是你转型过程中最具杀伤力的护城河。

```text
┌──────────────────────────────────────┐          ┌──────────────────────────────────────┐
│         视频编解码 (Codec) 技能库     │ ───────► │         AI 芯片 (NPU) 对应能力        │
├──────────────────────────────────────┤          ├──────────────────────────────────────┤
│ 运动估计 (ME) 滑窗搜索 (SAD/SSD)     │ 映射转化 │ 卷积滑窗乘加阵列 (Conv MAC Array)     │
│ 宏块行缓冲 (Line Buffer) 与环形缓冲  │ 映射转化 │ 特征图 Line Buffer 与滑动窗口重叠复用  │
│ 帧内/帧间多维跨步 DMA (Raster/Stride)│ 映射转化 │ 张量多维跨步 DMA (NCHW/NHWC Tensor)   │
│ DCT / 反变换 / 量化 / 反量化         │ 映射转化 │ 矩阵乘 (GEMM) / 定点反量化与缩放截断  │
│ 宏块参考帧 Ping-Pong 缓冲机制        │ 映射转化 │ 计算与访存双缓冲 (Ping-Pong) 延迟隐藏 │
│ 语法解析器与 CABAC 状态机 (FSM)      │ 映射转化 │ 控制子系统 (FSM / 指令译码分发 / 同步)│
└──────────────────────────────────────┘          └──────────────────────────────────────┘
```

|:---|:---|:---:|:---|

## 四、 简历王牌实战项目精选指南

> 💡 **原则**：不要在简历上写“跑了 PyTorch 识别模型”，面试官只看 **RTL 级微架构实现、总线仲裁、流水线气泡消除和时序收敛**！

### 选项 A（推荐：经典工业级实操）—— 基于 NVDLA 开源架构的微架构增强设计
* **项目切入点**：
  NVDLA 原生架构对标准卷积极其高效，但在跑 **MobileNet 的 Depthwise 卷积** 时，由于缺少跨通道规约累加，导致 16×16 MAC 阵列利用率暴跌至 6.25% ~ 18.75%。
* **你的微架构改造（写进简历的亮点）**：
  1. **可重构加法树（Reconfigurable Adder Tree）设计**：在 CACC 模块中增加旁路 MUX，使得 16-to-1 的大加法树能动态拆解为 4 组独立的 4-to-1 小加法树，支持空间 4 像素同时并发计算。
  2. **交织 Line Buffer 优化**：重新设计卷积行缓冲读取逻辑，消除 $3\times3$ 滑窗重叠区域从片外 SRAM 的二次冗余读取。
* **量化成果**：
  *“在维持原阵列面积增加仅 4.2% 的前提下，将 Depthwise 卷积的 MAC 硬件利用率从 18.75% 提升至 75%，端到端推理时延降低 58%。”*

---

### 选项 B（进阶：大模型热点追踪）—— 针对 LLM Attention 的轻量分块加速核设计
* **项目切入点**：
  实现一个支持 FlashAttention-like 在线 Softmax 的硬件计算小核。
* **你的微架构设计**：
  1. **双缓冲脉动矩阵乘（Systolic GEMM Array）**：支持 $Q \times K^T$ 矩阵乘法，采用 Output Stationary（OS）数据流减少部分和搬运。
  2. **硬件在线 Softmax 流水线**：设计硬件动态最大值追踪（$m_{new} = \max(m_{prev}, x)$）与泰勒展开/查找表指数单元（Exp LUT），实现不落盘直接与 $V$ 矩阵相乘。
  3. **基于信号量的硬件流控**：设计双信号量握手协议，实现片外搬运与片内矩阵乘的 100% 延迟隐藏。
* **量化成果**：
  *“设计了 16×16 INT8/FP8 紧耦合 Attention 算子核，片上 SRAM 访问次数降低 4×，在 28nm 工艺下达到 800MHz 时钟频率，计算单元有效流水率达 92%。”*

---

### 选项 C（绝杀：独家护城河）—— AI-ISP / 神经视频编码器（NVC）联合加速器
* **项目切入点**：
  结合你的 Codec 视频专长，设计一个专门用于智能安防或超分（Super-Resolution）的“传统视频处理 + AI 滤波”异构融合加速引擎。
* **你的微架构设计**：
  1. 将传统视频反量化/去块滤波（Deblocking）的数据流直接通过片上共享 SRAM 旁路灌入 AI 卷积阵列，消除往返 DDR 的开销。
  2. 统一设计兼容 2D 视频宏块跨步与 3D 张量排布的多维 DMA 引擎。
* **量化成果**：
  *“打通了传统视频解码流水线与 NPU 超分网络的片上直通链路，消除 65% 的片外高分辨率视频帧回写带宽，整体系统功耗节省 35%。”*

## 五、 工业级高频面试八大核心考点突破

### Q1：MAC 阵列常见的三大数据流（WS, OS, IS）优缺点及如何选型？
* **核心答法**：
  - **Weight Stationary（权重固定）**：权重常驻寄存器，特征图广播流动，累加和沿脉动传递。适合卷积层（权重被多个像素反复复用），代表架构：TPU v1。
  - **Output Stationary（输出固定）**：部分和锁定在 MAC 寄存器内累加，输入与权重流式灌入。极大地消除了部分和向外读写的带宽压力。适合全连接层（GEMM）或大矩阵乘。
  - **Input Stationary（输入固定）**：特征图像素常驻片内，权重流过。需要庞大的外部累加器，工业界极少单独使用。

### Q2：如何用双缓冲（Ping-Pong Buffer）完全隐藏搬运延迟？数学临界条件是什么？
* **核心答法**：
  - 硬件设立两组独立 SRAM（Buffer A/B），一组供 DMA 写入，另一组供 MAC 读取，算完瞬间角色翻转（Swap）。
  - **数学临界条件**：$T_{comp} \ge T_{comm}$（计算时间大于等于数据搬运时间）。
  - 若 $T_{comp} < T_{comm}$，系统沦为带宽受限（Memory-bound），MAC 产生停顿。编译器可通过增大输出通道切块（$T_{cout}$）或 Batch 增加权重复用，拉长计算时间以掩盖搬运。

### Q3：多 Bank SRAM 的低位交织原理是什么？如何解决 Bank 冲突？
* **核心答法**：
  - **低位交织**：将地址末位（如 8 个 Bank 对应末 3 位）作为物理 Bank ID，把连续地址像发扑克牌一样均匀散开在不同实体 SRAM 上。
  - **优势**：连续 Burst 访问时 8 个 Bank 可在一拍内并行吐出 8 笔数据，吞吐翻 8 倍。
  - **冲突解决**：采用交织寻址规避连续冲突；对于权重等高频广播数据采用片上副本复制（Data Replication）；设置访问仲裁器与 1 拍缓冲等待。

### Q4：为什么大模型推理的 Prefill 和 Decode 阶段硬件性能特征完全不同？
* **核心答法**：
  - **Prefill 阶段**：一次性输入几百上千个 Prompt Token，计算是大矩阵乘大矩阵，算术强度极高（几十到上百 OPs/Byte），硬件处于 Roofline 模型的**右侧水平区（Compute-bound）**，瓶颈在算力利用率。
  - **Decode 阶段**：自回归生成，每次只输入 1 个 Token，但每步都要把整个大模型数十 GB 的全部权重从片外 DRAM 搬一遍，算术强度极低（< 1 OP/Byte），处于 Roofline **左侧倾斜区（Memory-bound）**，性能完全由片外内存带宽决定。

### Q5：FlashAttention 为什么能极大提速？硬件层面是怎么节省带宽的？
* **核心答法**：
  - 传统 Attention 必须把 $S = Q \times K^T$（$N \times N$ 大小的中间注意力矩阵）完整写回片外 DRAM，再读出来做 Softmax，访存复杂度是 $O(N^2)$。
  - FlashAttention 利用**在线 Softmax（Online Softmax）** 数学变换，把 $Q, K, V$ 分块调入片上极快的高速 SRAM，在片上直接完成局部 Softmax 与乘 $V$ 的全部累加，**绝不把 $N \times N$ 的庞大中间矩阵写出到片外**，将片外访存量直接降到 $O(N)$。

### Q6：为什么说纯硬件状态机（FSM）适合端侧，而标量处理器（RISC-V）适合云端与车载？
* **核心答法**：
  - **FSM**：纯电路连线，几十门到上万门电路，几乎零面积零取指功耗，单拍响应；但流片即锁死，无法更新新算子。适合功耗极低（<1.5W）、模型固定（如 MobileNet）的端侧微型芯片。
  - **RISC-V 标量核**：通过执行固件（Firmware）调度硬件单元，面积与功耗略大，但灵活性满分。面对大模型每月一变的算法演化，只需升级固件即可支持新网络，保护数亿元芯片流片资产。

### Q7：多核加速器中，为什么 16 核系统更青睐 2D-Mesh 而不是 Crossbar 或 Bus？
* **核心答法**：
  - **Crossbar**：16 核全互连需要 $16 \times 16 = 256$ 个交叉开关，布线拥塞（Routing Congestion）会导致硅片面积暴涨、时序难以收敛。
  - **Bus / Ring**：多核竞争总线严重，单环跳步延迟随核数线性暴增（16核达 8 跳），带宽瓶颈显著。
  - **2D-Mesh**：规整度极高，每个节点仅连上下左右 4 个邻居，金属走线极短且整齐；平均跳步短；搭配 X-Y 维序路由数学证明天然无死锁，且非常利于分散放置双侧对称的内存控制器（MC）。

### Q8：你在 Codec 中做过复杂时序收敛与 CDC（跨时钟域），在 AI 加速器中有何异同？
* **核心答法**：
  - **相同点**：都需要严格遵循单双比特同步器、异步 FIFO 握手机制，控制信号严格打拍；
  - **AI 芯片特有挑战**：AI 加速器片上拥有成千上万个 MAC 乘法器同时翻转，会引发严重的 **时钟树功耗（Clock Tree Power）** 与 **IR-Drop（动态压降）**。因此必须在微架构上引入密集的门控时钟单元（ICG）以及脉动延时打拍（Skewing），使阵列计算活动在空间和时间上错开，抑制峰值瞬态电流。
